# NetVisor Modular Security Engines Architecture

This document describes the decoupled, engine-based architecture designed for the NetVisor NDR platform.

## 1. Engine Responsibilities

The detection and analysis logic is partitioned into six core security engines:

### A. Device Engine
*   **Purpose**: Identify and catalog all active devices in the network scope.
*   **Key Capabilities**:
    *   Perform MAC vendor lookup (OUI).
    *   Sniff multicast name services (mDNS, SSDP).
    *   Parse DHCP Option 55 parameter requests to fingerprint exact operating systems.
*   **Output**: Structured findings indicating device identity hints, device type, and confidence evidence.

### B. Application Engine
*   **Purpose**: Classify flow traffic into distinct business and consumer application categories.
*   **Key Capabilities**:
    *   Inspect DNS queries and TLS SNI (Server Name Indication) directly from raw packets.
    *   Implement JA4 TLS client fingerprinting.
    *   Map ASNs to major cloud services (AWS, Google, Microsoft Teams, Slack).

### C. VPN Engine
*   **Purpose**: Detect anonymous proxies, commercial VPNs, and encrypted tunneling connections.
*   **Key Capabilities**:
    *   Run offline ASN reputation lookups against a local MaxMind database.
    *   Analyze flow signatures for specific protocols (WireGuard, OpenVPN, IPsec).
    *   Analyze session behavioral patterns (persistence, MTU clamping, symmetric flow bytes).

### D. Threat Engine
*   **Purpose**: Identify active network intrusions and malicious activities.
*   **Key Capabilities**:
    *   Port scanning (high frequency ports connection attempts).
    *   C2 Beaconing (periodic intervals with low variance).
    *   DNS Tunneling (entropy check and subdomain blooms).
    *   Data Exfiltration (large volume uploads).
    *   Brute Force Attack (repeated failed connections on SSH, RDP, SMB).

### E. Risk Engine
*   **Purpose**: Calculate the final severity level and risk score for endpoints.
*   **Key Capabilities**:
    *   Aggregates findings received from all other engines.
    *   Applies time-to-live (TTL) decay and alert suppression rules.
    *   Correlates multiple signals (e.g. VPN + Port Scan = High Risk).

### F. AI Engine
*   **Purpose**: Translate structured security telemetry and alerts into natural language.
*   **Key Capabilities**:
    *   Query LLMs to explain the significance of detected threats.
    *   Provide immediate remediation guidelines for network administrators.

---

## 2. Shared Engine Contracts

To maintain strict boundaries between workflow management and detection logic, all engines communicate using unified contracts located in `shared/engine/`:

*   **`Severity`**: An enum mapping finding importance (`INFO`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
*   **`Finding`**: A single diagnostic observation containing classification details, target context, and supporting evidence.
*   **`EngineResult`**: A wrapper encapsulating lists of findings generated by a single analysis run.
*   **`BaseEngine`**: The abstract base class that all engines inherit, enforcing standardized signature methods (`analyze` and properties for `name` and `version`).
