# Finding Schema Specification

All diagnostic results generated by NetVisor engines are formatted as standard `Finding` objects. This document defines the schema constraints and expected data formats.

## 1. Schema Properties

| Field | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| `engine` | `str` | Name of the engine producing this finding (e.g. `"device"`, `"vpn"`). | Yes | N/A |
| `finding_type` | `str` | Specific signature identifier (e.g. `"device_profiled"`, `"port_scan"`). | Yes | N/A |
| `severity` | `Severity` | Threat classification level enum (`Severity` values). | Yes | N/A |
| `confidence` | `float` | Probability of accurate classification between `0.0` and `1.0`. | Yes | N/A |
| `evidence` | `List[str]` | Human-readable log segments or triggers proving finding. | No | `[]` |
| `timestamp` | `datetime` | UTC timestamp of observation. | No | `now(UTC)` |
| `ttl` | `int` | Lifetime of finding in seconds before decaying from cache. | No | `300` |
| `target_ip` | `Optional[str]` | Target IP address under inspection. | No | `None` |
| `target_mac` | `Optional[str]` | Target hardware address (if local scope). | No | `None` |
| `mitre_attack_id`| `Optional[str]` | MITRE ATT&CK technique code (e.g. `"T1046"`). | No | `None` |
| `details` | `Dict[str, Any]` | Engine-specific raw metadata for tracking/debugging. | No | `{}` |

---

## 2. Engine Detail Schemas (`details`)

### Device Engine (`engine = "device"`)
*   `hostname`: Hostname resolved.
*   `vendor`: Hardware vendor resolved.
*   `device_type`: Inferred type (e.g. `"Laptop"`, `"Printer"`).
*   `confidence_level`: Low/Medium/High categorization.

### VPN Engine (`engine = "vpn"`)
*   `provider`: Detected commercial VPN name.
*   `score`: Raw combined heuristics score.
*   `reason`: Aggregate reason string.

### Application Engine (`engine = "application"`)
*   `application_name`: Final application classification.
